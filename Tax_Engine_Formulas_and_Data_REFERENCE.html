TAX ENGINE — FORMULAS & DATA REFERENCE

All calculation logic and parameter data for the ONYX Ledger engine · Tax years 2025 & 2026 · Prepared August 2026

How to use this: every formula here is deterministic — the engine is these formulas plus annual parameter tables. A companion file, tax_engine_params.json, holds the same numbers in machine-readable form so the code reads config, never hardcoded values. Golden rule: the 2025 figures apply to 2025 income (returns filed spring 2026); 2026 figures apply to income being earned now.

VERIFICATION STATUS (checked 13 August 2026): federal brackets (both years), the basic personal amount and its phase-out, Canada employment amount, age amount, medical threshold, disability amount, spouse amount, CPP, EI (federal and Quebec), RRSP/TFSA limits, the OAS clawback thresholds, capital-gains inclusion, dividend gross-up and federal dividend tax credit rates, and all provincial and territorial brackets for 2025 and 2026 were confirmed line-by-line against CRA's published pages. Items still unverified are listed in §15 and flagged "_verified": false in the JSON.

This is not a compliance certification. Matching CRA's published numbers does not make software CRA-certified — certification is earned only by passing the CRA's own test returns during the NETFILE certification cycle.

1. THE CORE PIPELINE — HOW EVERY RETURN COMPUTES

totalIncome      = employment + selfEmployment + interest + grossedUpDividends
                 + taxableCapitalGains + otherIncome            // T1 line 15000
netIncome        = totalIncome − deductions                     // line 23600
                   // deductions: RRSP, FHSA, childcare, union dues,
                   // moving, support paid, carrying charges
taxableIncome    = netIncome − additionalDeductions             // line 26000
                   // e.g. losses carried forward, security options deduction

fedTaxBeforeCredits  = applyBrackets(taxableIncome, FED_BRACKETS[year])
provTaxBeforeCredits = applyBrackets(taxableIncome, PROV_BRACKETS[prov][year])

fedTax  = max(0, fedTaxBeforeCredits  − fedNonRefundableCredits  − dividendTaxCredit_fed)
provTax = max(0, provTaxBeforeCredits − provNonRefundableCredits − dividendTaxCredit_prov
                 + provincialSurtax)                             // ON only, see §4

totalPayable = fedTax + provTax + CPP_selfEmployed_owed
refundOrOwing = amountsPaid − totalPayable
                // amountsPaid: tax withheld on T4/T5 slips (box 22),
                // instalments paid, refundable credits (CWB, etc.)
                // positive = refund, negative = balance owing

function applyBrackets(income, brackets):        // brackets sorted ascending
    tax = 0
    for each (threshold, rate, nextThreshold) in brackets:
        slice = min(income, nextThreshold) − threshold
        if slice <= 0: break
        tax += slice × rate
    return tax

3. FEDERAL NON-REFUNDABLE CREDITS (the big ones)

All credits below are amounts; convert to tax reduction via: creditValue = amount × lowestFedRate (14.5% in 2025, 14% in 2026). Credits can reduce tax to zero but never below (except refundable ones, §9).

3.1 Basic Personal Amount (BPA) — with high-income phase-out

// 2025: max 16,129, min 14,538, phase-out range = 4th bracket (177,882 → 253,414)
// 2026: max 16,452, min ~14,829 (verify), range 181,440 → 258,482
if netIncome <= rangeStart:      bpa = bpaMax
else if netIncome >= rangeEnd:   bpa = bpaMin
else: bpa = bpaMax − (bpaMax − bpaMin) × (netIncome − rangeStart) / (rangeEnd − rangeStart)

6.1 Capital gains

8. REFUND ESTIMATION (the number on your dashboard)

estimatedRefund = taxWithheld                       // Σ T4 box 22, T5 withholding
                + instalmentsPaid
                + refundableCredits                  // CWB, eligible educator, etc.
                − totalPayable                       // from §1
// CONFIDENCE: show a range, not a point. Drivers of uncertainty:
//   missing slips (AFR pull incomplete), unentered deductions, pending RRSP (first-60-days)
// display: "Estimated refund $X – $Y" until all declared sources are entered
Why withholding ≠ tax owed (and refunds exist): employers withhold per-paycheque as if that pay rate ran all year, ignoring RRSP contributions, medical, donations, and multi-job effects. Two jobs = each withholds as if it's the only income = usually a balance owing. Detect the multiple-T4 case and warn the user early — it's the #1 "surprise bill" scenario.

9. MARGINAL vs EFFECTIVE RATE (dashboard metrics)

marginalRate  = fedRate(taxableIncome) + provRate(taxableIncome)      // rate on the NEXT dollar
effectiveRate = (fedTax + provTax) / totalIncome                      // average on ALL dollars
// example, ON 2025 @ $80,000 taxable: marginal = 20.5% + 9.15% = 29.65%
// note for accuracy: marginal rate near credit phase-out zones (BPA clawback, age amount,
// OAS clawback) is HIGHER than the bracket rate — compute marginal numerically:
trueMarginal = tax(income + 100) − tax(income)) / 100                 // robust method, use this

10. SIMULATOR FORMULAS (your differentiator)

10.1 RRSP contribution simulator

// NEVER use flat "contribution × marginalRate" — wrong when crossing brackets. Do this:
taxSaving = totalTax(taxableIncome) − totalTax(taxableIncome − contribution)
// where totalTax = fed + prov, full pipeline both times. Also recompute income-tested
// benefits (CCB, GST credit, OAS clawback) — RRSP deductions can INCREASE benefits;
// showing that combined number is a feature competitors don't have
alsoShow: refundPerDollar curve, room remaining, over-contribution warning

10.2 FHSA simulator

same taxSaving formula as RRSP (it's a deduction), capped at min(8000 + carryforward, 40000 − lifetimeUsed)
comparison view: FHSA vs RRSP-HBP vs TFSA for a down-payment goal

10.3 Capital gains timing simulator

taxThisYear = totalTax(income + 0.5 × gain) − totalTax(income)
taxNextYear = totalTax(projectedNextIncome + 0.5 × gain) − totalTax(projectedNextIncome)
show: difference, plus December/January split option (half the gain in each year
      uses two sets of brackets — legitimate and material for large gains)

10.4 Donation pooling simulator

// carrying forward 5 yrs & combining spouses beats claiming $150/yr repeatedly,
// because only amounts OVER $200/yr earn the 29% rate:
annualClaim  = 5 × (lowestRate × 150)                          // five small claims
pooledClaim  = lowestRate × 200 + 0.29 × (750 − 200)           // one pooled claim

score = Σ weightedComponents, scaled to 0–100:

13. THINGS YOUR DEMO IMPLIES THAT ARE WRONG OR DEAD — FIX BEFORE CODING

  • Work-from-home $2/day flat method is DEAD (ended after 2022). WFH now requires the detailed method: employer-signed T2200 + T777 form, claiming workspaceArea/homeArea × eligibleHomeCosts (rent, utilities; commission employees add more; mortgage principal never eligible). The demo's "+$180 WFH" card must be built on this, not the flat rate.
  • Consumer carbon rebate (CCR) ended April 2025 — no rebate card in the product.
  • Capital gains inclusion stays 50% — the announced 2/3 increase was cancelled; don't build remnants of it.
  • The lowest federal rate is 14.5%/14%, not 15% — any calculator copied from a pre-2025 tutorial will be wrong on every bracket-1 dollar and every credit.

14. HOW TO STRUCTURE THIS IN CODE

  • Everything above is config, not code. One tax_engine_params.json keyed by year → jurisdiction → parameter (companion file provided). The formulas never change annually; only the tables do. Annual update = new JSON block + rerun test suite.
  • Money math: compute in cents (integers) or a decimal type — never floating point. CRA rounding: per-line rounding to the cent; final balances to the dollar follow form rules.
  • Test harness from day one: build ~50 personas (single T4; two T4s; T4+RRSP; self-employed; investor with gains/dividends; senior with OAS; parent with CCB; each province) and lock expected outputs. When CRA's certification test returns arrive, they slot into the same harness. Cross-check personas against an existing certified product's results while developing.
  • Every computed number carries provenance: store which formula + which parameters produced it, so the UI can show "why" (trust feature) and support can debug (liability feature).
